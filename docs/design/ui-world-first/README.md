# 地図中心UIの設計資料

最終更新: 2026-09-17。現行仕様は [地図中心のUI](../../ui-world-first.md)、未実施の評価は [UI受入計画](../../plans/ui-usability-improvements-plan-2026-09-14.md)を参照する。

## 採用した考え方

地図の閉塞感、2段化による一覧密度低下、記号と文字の不揃い、メニューによる案内遮蔽が再設計の出発点だった。文字を小さくするのでなく、常時表示する情報と必要時に開く情報を分けた。

| 比較案 | 判断 |
| --- | --- |
| 常駐する左右パネルの縮小 | 個人数値が画面を占め続けるため主方式にしない |
| 地図中心・固定の操作入口・必要時の詳細 | 採用。役割を文字で示し、管理・詳細・表示設定を一つの枠で切り替える |
| 右クリック中心でUIを隠す | 発見しにくいため主方式にしない。使い魔詳細にも作業範囲の入口を置く |

情報は「常時の人数・時間・要対応と操作入口」「対象や操作に応じた役割・状態・次の入力」「自分で開く一覧・設定・Help」の3層とする。選択、カメラ移動、詳細の固定は別操作。管理の情報量と文字サイズは維持し、設定済みエリアも通常時に残す。高度な範囲編集は必要時に展開する。

2026-09-15の設計時に一次資料を確認した記録。各資料の版の事例であり、現行版全体の評価ではない。本作への適用は設計判断で、元ゲームの効果測定ではない。

| 事例 | 本作への適用 |
| --- | --- |
| Factorio 0.17の在庫と独立した固定quickbar。[FFF278](https://www.factorio.com/blog/post/fff-278) | 主操作の位置を固定し、建築を絵・名前・用途で選べるようにする |
| Factorioの検索できるtips、対象tooltip、実演。[FFF361](https://www.factorio.com/blog/post/fff-361) | 目の前の対象に短い説明を出し、任意ガイドで実状態を追う。実演エンジンは新設しない |
| Cities: Skylines IIの自転車Info Viewで利用状況や駐輪場所を確認する設計。[公式Dev Diary](https://www.paradoxinteractive.com/games/cities-skylines-ii/news/dev-diary-building-for-bicycles) | 担当・保管・給電・部屋を目的別に地図へ表示し、凡例と解除入口を残す |
| Victoria 3の任意のHow/Why説明とゲーム内課題。[Dev Diary 51](https://www.paradoxinteractive.com/games/victoria-3/news/dev-diary-51-tutorials) | 強制ツアーにせず、採取から選んだ休息所の搬入・施工・完成まで案内する |
