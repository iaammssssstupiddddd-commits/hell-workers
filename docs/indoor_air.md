# 室内空気と空調

## M2〜M7 ドラフトの遊び方

「建てる」から「空調・水道」を開く。設備14種は既存の資材搬入・施工で完成し、設備本体の記号から種類を識別できる。個別メッシュ・容量・消費電力は調整中。

| 段階 | 操作・成立条件 | 確認先 |
| --- | --- | --- |
| M2 | 室内の給気機・排気機を外壁の風穴に隣接させるか、上下左右につながる室内の風道で結ぶ。別の外壁端末への補給経路を用意する。煙突には屋外との温度差が必要 | 風穴の正味流量、床の有効外気、機器の接続先・給電待ち |
| M3 | 横3×縦2の取水門を河岸に建てる。横の3マスが川に接し、横位置が重なる工区が32タイル以内に一つ必要。取水門はそのYardから受電する。地下の導水管をドラッグし、室内の浄化盤までつなぐ。Shiftを押してなぞった管を撤去できる | 導水管ツールで地上建物の下の管を表示。機器直下・四隣接から同じ管網を利用 |
| M4 | 水が届く浄化盤と良好な換気が揃うと部屋を認可する。断水すると浄化盤が止まり、復旧時に自動再開する | 床の「排泥」「認可」。仮設のタンク・泥ミキサー・Soul Spaは給水条件の対象外 |
| M5 | 魂、泥ミキサー、Soul Spa が発生させる瘴気を追跡する。局所排気口は同一セルまたは上下左右の発生源を実際の正味排気量に応じて捕集する。循環ろ過機は室内の瘴気を処理する | 濃度と仮想1秒当たりの増減 |
| M6 | 冷暖房室内機のマンハッタン距離2以内に室外機を置く。給水した加湿器・除湿器は湿度40〜60%の範囲を目標にする。熱交換器は部屋の実際の屋外給排気の小さい方を限度に顕熱を回収する | 温度、相対湿度、水蒸気濃度、室外機の放熱。屋外を温度固定の境界とし屋外機の吸放熱を符号付きで表示 |
| M7 | 給気機・排気機・局所排気口と同じ建築カードで完成機をクリックして標準・省エネ・強運転を切り替える。標準では汚染濃度や冷涼な外気に応じて風量と電力需要が変化する。床には標準運転の増風要求、機器には選択した運転設定を表示する。設備詳細から配電優先度を設定する | 外気条件は30仮想秒ごとに変化。冷房は25℃超で入り23℃未満で切れ、暖房は19℃未満で入り21℃超で切れる |

### 計算と保存

部屋の床と囲い庭を混合容積とする。風穴列の壁内接点は容積0の接続点で、扉は常に通風を遮る。外壁を介した熱伝達、開口の正味流・双方向交換、内部発生、除湿・加湿・凝縮の潜熱を仮想1秒ごとに計算する。三項目を後退オイラー法で解き、流量や機器条件が変化するまで分解済みの行列を再利用する。ろ過は瘴気収支の対角項に入り、外気供給には加算されない。室外機は暖房時に採熱し、冷房時には除去熱と運転電力を屋外へ排出する。地形や屋外各セルの温度は追跡しない。

物理時刻と1秒未満の端数、床座標、水蒸気・顕熱・瘴気の濃度、制御の履歴と機器設定を保存する。部屋の分割・結合では重なる床ごとの容積で引き継ぎ、新しく囲った床はその時刻の外気で初期化する。運転状態は再計算される。在室・発生源は各固定ステップでサンプリングする。閾値での丸め誤差が増風・温湿度制御・煙突の段階を切り替えないよう、判定に限り10⁻⁹の許容差を設ける。本番の更新処理を使った256室の実測値を次に示す。

### 気象・設備の変更時に再利用する計算

各区画の温度・水蒸気・瘴気は仮想1秒ごとに更新する。完成した通気設備で連結する区画を一つの空気系とし、共有壁の伝熱でつながる区画まで含めた系で熱を解く。外気境界は異なる棟を連結しない。部屋や囲い庭が変わると床の重なりで保存状態を引き継ぎ、形状が等しい系は、最小次数順の消去順序と係数の書き込み位置を共有する。数値係数は建築・ロード時の形状から再生成する。

圧力の分解と基準風による流量は形状確定時に求める。運転中は符号付きの風係数と機器の駆動圧に対する流量を加算する。端末圧が変わった系でだけ機器の流量を再計算する。正味流量が変わると、双方向交換を含む新しい流量から希釈・水蒸気・瘴気・熱の数値係数を作り直す。ろ過量だけが変わった場合は該当する空気系の瘴気の分解を更新する。発生量と外気温湿度は毎ステップの右辺に入る。扉は通風経路に含めず、開閉で係数を更新しない。[空調計算](../crates/hw_infra/src/ventilation/network.rs)・[固定した消去順での数値分解](../crates/hw_infra/src/ventilation/sparse.rs)

### 風量変更時の書き戻し

数値計算は、風・端末の駆動圧・室のろ過量を前回と照合する。端末・ろ過量の変更を所属する空気系に渡し、流量が変わった空気系を含む熱系で熱の係数を更新する。熱・水蒸気・瘴気の状態と設備制御は全室で仮想1秒ごとに進み、発生量などの一時配列は次の更新で再利用する。換気の数値を部屋と風穴に書き戻す範囲は、風量が変わった空気系の全室・全開口。初回とロード時は全系を初期化し、未接続の風穴は形状更新時に表示を設定する。風穴の説明は選択・ピン留め中の数値から作り、輪郭は換気区分が変化したときと子の輪郭を作り直したときに着色する。[空気系の更新](../crates/hw_infra/src/ventilation/network.rs)・[部屋と風穴への反映](../crates/bevy_app/src/systems/ventilation/publication.rs)

## 自然換気の配置例（機械設備なし・基準風）

「この部屋へ新しい空気が届き、室内で発生したものを外へ逃がせるか」を判定する。以前は完成した風穴に一律の供給量を与え、共有壁では両室に半分ずつ配っていた。そのため完全に閉じた二室でも「良好」になっていた。

自然換気の通り道は完成した「叫びの風穴」。扉は開閉・施錠のどの状態でも部屋の境界になる。屋外はマップ端から外壁を横切らずに到達できる空間。囲い庭へ空気を通すには、庭と屋外をつなぐ風穴が要る。建築中の風穴では元の壁が空気を遮る。厚い壁ではまっすぐ並んだ風穴が直列につながる。通風面が定まらない角では、選択パネルに「通風面が未接続」と表示する。

| 同じ風穴を使った配置 | 有効外気 / 必要量（ゲーム単位） | プレイヤーから見える結果 |
| --- | --- | --- |
| 密閉した3×3室と4×3室を共有風穴で接続 | 西 0.00 / 0.45、東 0.00 / 0.60 | 両室とも紫の「外気交換なし」。共有風穴のパネルで外気経路がないことを確認できる |
| 独立した3×3室の西外壁に一つ | 0.20 / 0.45 | 一つの穴を空気が双方向に出入りする。換気不足 |
| 同じ室の西外壁に二つ ／ 西壁と東壁に一つずつ | 0.40 ／ 1.40（必要量 0.45） | 二つの外壁の圧力差で通風する配置は良好 |
| 最初の二室の西端と東端にも風穴を追加 | 西 0.72 / 0.45、東 0.56 / 0.60 | 共有風穴の正味通風は西→東に0.67。東室は西室で生じた負荷も受け、不足が0.04残る |

床の詳細には換気状態、有効外気、必要量、不足量、屋外からの流入と隣室側からの流入を表示する。「有効外気」は各室に仮定した発生負荷をどれだけ薄められるかを、相当する外気量に換算した値。流入量には同じ空気が隣室を経て戻る分も含むため、二つの流入表示を足して判定することはできない。共有風穴を選べば、その場で流れる向きと両側の部屋の結果を読める。

### 計算の前提

- 各室の空気は均一に混ざり、天井高は共通とする。次の配置例では西から東への基準風を用い、屋外に露出した西面の圧力を +1、東面を −1、南北面を 0 とする。圧力、量、必要量はいずれもゲーム用の相対値。
- 開口の正味流量は「通りやすさ × 両端の圧力差」。風穴の通りやすさは1。各区画で流入と流出が釣り合うように室圧を求める。さらに同じ開口で両方向へ各 `0.20 × 通りやすさ` の混合を認めるため、一面の開口でも外気と少し交換できる。
- 屋外の基準濃度を基点に、各室に床1枚当たり0.05の仮想発生負荷を置く。気流に沿って運ばれる負荷が定常状態で釣り合う濃度上昇を求め、`有効外気 = その室の発生負荷 / 濃度上昇` とする。囲い庭の負荷は0。外気につながらない系の有効外気は全室0。基準に届く室を「良好」、届かない室を「換気不足」とする。M5の瘴気濃度は、実際の発生・除去と時間経過から別に計算する。
- 屋外境界・部屋・完成設備から圧力と流量を求める。どちらも派生値で、一時停止中にロードしても同じ構造から復元する。

屋外と開口間の圧力差、単一開口の双方向交換、複数室をまたぐ汚染物質の移送をゲーム向けに簡略化した。風穴の寸法から現実の換気量や衛生基準を推定する用途は想定していない。[ASHRAE Handbook「Ventilation and Infiltration」](https://handbook.ashrae.org/Handbooks/F25/IP/F25_Ch16/F25_Ch16_ip.aspx)・[NISTのマルチゾーン空気流・汚染物質モデル](https://www.nist.gov/services-resources/software/contam)

## CPU負荷を抑える計算モデル

M1では、建築形状の変更世代を毎フレーム確認し、前回と同じなら終了する。平常時と扉操作時は開口一覧を調べず、作業配列も確保しない。部屋が確定した構造変更時にだけ、次の手順で各室の値を更新する。[更新処理](../crates/bevy_app/src/systems/ventilation.rs)・[換気計算](../crates/hw_infra/src/ventilation.rs)

### 何を、いつ計算するか

計算単位は部屋と開口。屋外は既知の圧力を持つ境界として各外壁に与える。風穴を介して内部でつながる部屋・囲い庭・壁内の中継点を同じグループにまとめる。別棟が同じ屋外に面していても、その二棟は個別に解ける。

| 入力の変化 | 更新する範囲と処理 |
| --- | --- |
| 建築の完成・撤去・部屋の分割や統合、ロード | 部屋検出の確定後に屋外をマップ端から再探索し、グループと派生値を作り直す。外壁一枚の撤去で遠くの囲い庭まで屋外に変わり得るため、ここでは全面探索を許す。ロード・ロールバックは古い参照を破棄する |
| 扉の開閉・施錠 | 換気の入力は同一。再探索・再計算は0回 |
| 将来のファン・ダンパーの出力変更 | 変更された機器に接続する区画群の気流を更新する |
| 将来の天候・発生源の変化 | 風圧が変わった外壁や、温度差で駆動圧が変わった煙突のグループだけ気流を更新。瘴気の発生量や外気湿度だけが変わった場合は物質収支の入力を更新する |
| 入力変化なし・床の選択・カメラ移動 | M1は変更世代を1回比較して終了。開口走査、行列の組立、作業バッファ確保は各0回。床・風穴・境界色は最後に確定した同じ計算結果を読む |

### 自然換気の解き分け

構造の確定時に、室間の通風経路をたどって成分を作る。各成分は次の順で処理する。

1. **屋外に通じない受動換気区画**。有効外気と正味通風は0。開いている室間開口では各方向の混合量 `0.20 × 通りやすさ` を流入の内訳に残す。行列の求解は0回。将来、密閉区画の内部でファンが運転すれば、外気量は0のまま機械による循環を別途解く。
2. **外壁開口だけを持つ一室**。開口の通りやすさを `g`、各開口の屋外圧を `P外` とすると、室圧は `Σ(g × P外) / Σg`。各開口の室外向き正味流量は `q = g × (室圧 − P外)`。外気流入は `0.20g + max(−q, 0)` で、その合計がこの室の有効外気になる。開口を二巡すればよい。開口ゼロは手順1に含める。
3. **屋外に通じる複数区画**。対象成分だけに現行の疎な圧力収支と希釈収支を適用し、各1回解く。室間から来た空気は上流の負荷を引き継ぐ。区画・開口を安定した順に並べ、解を各室と各開口に戻す。

平常時と扉操作時の変更確認はマップの広さによらず定数時間。建築変更時にはマップを探索する。成分の分割は区画数と開口数の和に比例し、多室の疎行列の計算時間は接続の形にも依存する。

### 瘴気・水蒸気・熱の時間更新（当初の設計）

- 物理的な部屋と囲い庭に容積を与え、瘴気量・水蒸気量・熱量を各1値持つ。壁内やダクトの容積ゼロの中継点は、その瞬間の流入と流出を釣り合わせる。正の容積を持つ区画にも屋外境界にも通じず、発生源もない中継点だけの成分は丸ごと未知数から外す。両端のダンパーを閉じ、壁内の風穴を挟んで中継点同士だけで混合する場合もこれに含む。圧力と両方向の流量をキャッシュし、3種類の輸送に共用する。閉扉・壁越しの熱伝導には壁面の隣接関係も使う。
- 初期の更新幅は `Time<Virtual>` の **1秒**。動いている区画群だけを対象とする。機器・発生源の条件が途中で変わるときは、影響範囲を旧条件でその時刻まで進めてから切り替える。速度変更・低FPSでも未処理の仮想時間を引き継ぐ。一時停止時は蓄積を進めず、構造の換気診断は更新できる。セーブ時は確定済みの蓄積量と次の更新までの端数時間・必要な区間入力を保持し、再開で余分な積分を挟まない。
- 容積 `V`、物質濃度 `C = 物質量 / V`、発生量毎秒 `S` とする。一区間では **`V × (C新 − C旧) / Δt = S + Σ(流入量毎秒 × 流入元の新濃度) − Σ(流出量毎秒 × C新) − 除去量毎秒`** を成分単位で解く。屋外端は指定した背景濃度を用いる。室間の同じ移送を両端に逆符号で計上する。後退オイラー法と非負の移送・除去係数を使い、フィルター等の除去は新濃度に比例させる（係数は対象物質の処理風量×効率）。凝縮などの除去量は、その区間に利用できる物質量を上限とする。これにより1秒で室容積を超える空気が通る場合にも濃度を非負に保つ。流量・時間幅・除去係数が同じ物質は行列を共用できる。
- 熱は熱容量から温度を求め、移流と壁面の熱伝導、設備の発熱・排熱を収支に加える。除湿した水はドレンに計上し、対応する潜熱を熱収支に渡す。設備の停止・復帰などの制御は、確定した状態から次の運転状態を一度決める。
- 入力が一定で収支が釣り合い、制御の予定時刻もない成分は次の変化まで休止する。密閉中も発生源がある部屋、上流の変化を受ける下流室、壁越しに熱が移る隣室は更新対象とする。収支の微小値を表示上丸めただけの部屋を休止させず、長時間の蓄積を保つ。

| 段階 | 追加する設備・プレイヤーの選択 | 実装の受入条件 |
| --- | --- | --- |
| M2　機械換気・煙突 | 屋外端末、給排気を指定できる送風機、接続ダクト、溜息煙突。給気の取り入れ位置、排気先、補給空気の通り道と配電を選ぶ | 送風機は給電時に二端間の圧力差を作る。正味排気には同量の補給が必要。ダクト抵抗と経路に応じて実流量が変わり、閉塞・停電では駆動分が消える。室内循環だけの送風で外気は増えない。煙突は高さと基準の内外温度差による浮力で駆動し、温度計算導入後は実際の差に接続する |
| M3–M4　導水・部屋の認可 | 取水門・導水管・浄化盤を設置し、換気と排泥をそれぞれ検査する | 同じ部屋で換気不足と断水を個別に表示できる。行政上の認可と設備の運転条件を分け、換気量だけで瘴気による停止を発動しない |
| M5　瘴気・局所排気・ろ過 | 発生源の近くに排気口を置くか、室内の還気を対象物質用フィルターに通す。計器には濃度と増減を表示する | 屋外背景・魂や設備の発生・室間移送・排出・対象物質の除去から、時間ごとに物質量を更新。局所排気は近接した発生源の排出物を捕集率に応じて、室内に混ざる前に屋外へ排出する。同じ排気量の一般排気と比べて室内への負荷が減ることを確かめる。密閉・除去なしでは発生分だけ蓄積し、十分な換気を再開すると高まった濃度が徐々に低下する。循環ろ過は対象濃度を下げても外気量を増やさない。設備に瘴気停止を導入する場合は濃度・継続時間・復帰閾値を設備別に定義する |
| M6　暖冷房・湿度 | 熱源、室内機と室外機、加湿・除湿、熱交換換気を追加。外気導入、室温維持、排熱・ドレンの行き先を設計する | 外気・隣室からの移流、外壁の熱伝達、内部発熱、機器出力で顕熱を収支計算する。水蒸気の移送・発生・凝縮は別に追い、潜熱を熱収支に戻す。冷房の排熱には消費電力を含める。循環冷房だけで室温が下がっても、密閉室の外気量は0。熱回収は給排気間を移した熱量と両側の収支が一致する |
| M7　運転制御・エネルギー管理 | 風向・外気温・湿度を時間変化させ、外気冷房、最低外気量、可変風量、重要室への優先配電を設定する | 天候・在室負荷・停電を同じ設備配置で変え、給気量・濃度・室温・湿度・消費電力の応答を別々に確認する。切替にヒステリシスを持たせ、優先配電から復旧しても制御が振動しない |

M2は現行の部屋・開口・電力を利用できる。M5とM6に進む前に部屋容積と時間発展を導入する。セーブに保持するのは室内の物質量・水蒸気量・熱の蓄積量、運転設定と現在の制御モード、閾値超過の継続時間、上記の更新時刻の情報。部屋の一時Entityをキーにせず、旧床と新床の重複容積に応じて分割・統合し、室外へ開放した部分は屋外境界に計上する。新たに屋外を囲った部分は、その時刻の外気濃度・湿度・温度で初期化して境界からの移入に計上する。一時停止で物理時間が進まないこと、保存直後から再開した場合と連続運転した場合の収支が一致することを受入条件に加える。[EnergyPlus Engineering Reference（室内熱・水分収支）](https://energyplus.net/assets/nrel_custom/pdfs/pdfs_v25.1.0/EngineeringReference.pdf)
