## 1. 目的

最初に直すのは「保管範囲を削除」である。ある置き場の端を消しただけで、離れた置き場やTankに付属するバケツ置き場まで削除候補に入る。まず削除前後のセルと所有者をテストで固定し、その後で設定ファイルの保全と、終了したゲームを通常起動から再開する導線を整える。

運搬・休憩・建築操作は、資材があるのに仕事が始まらない、空いている施設を使えない、離したはずのドラッグが残る、といった具体的な場面で評価する。各項目の合格条件は下記に置く。

## 5. マイルストーンと合格条件

### M1　保管範囲の削除を、触れた置き場に限定する

`identify_removal_targets` はマップ上の全保管セルから矩形内を取り除き、残った連結成分のうち最大の一つ以外をすべて削除候補にする。例えば通常の置き場Aが横4セル、離れたBが2セル、さらに離れたTankの付属置き場が2セルなら、Aの端を1セル消すと、Aの残り3セルだけが残る計算になる。プレビューと確定はこの関数を呼び、確定側は対象をマップから取り出してエンティティを削除する。Tankの付属置き場も同じマップに登録される。[対象計算](../../../../crates/hw_world/src/zone_ops.rs#L21)・[プレビュー](../../../../crates/bevy_app/src/systems/command/zone_placement/removal_preview.rs#L24)・[確定](../../../../crates/bevy_app/src/systems/command/zone_placement/removal.rs#L85)・[Tankの登録](../../../../crates/bevy_app/src/interface/selection/building_place/placement.rs#L193)

1. 通常の保管セルをrootで列挙する。`Stockpile`・`StockpilePolicy`・生存するYardへの`BelongsTo`を確かめ、`WorldMap`の座標登録が同じセルEntityを指すものだけを渡す。設備付属セル、建設待ちセル、マップの古い登録を除く。[旧セーブ復元時の通常セルと設備の識別](../../../../crates/bevy_app/src/systems/save/rehydrate/tests/stockpile_policy.rs)
2. `hw_world`で「矩形に触れた、削除前から4近傍でつながる同じYardのセル」を成分ごとに分割する。矩形内が直接対象、残りの最大片以外が断片対象。同数なら各片の最小座標`(x, y)`を辞書順で比べ、大きい側を残す。隣り合う別Yardと、同じYard内の離れた置き場は別成分とする。
3. プレビューには矩形・操作種別・world epochと、直接／断片それぞれの座標・セルEntity・Yardを保持する。解放時は**前のフレームまでに表示した集合**と現状を全件照合してから、`clear_stockpile_tile_if_owned`とdespawnを適用する。解放フレームの再計算で表示済み集合を上書きしない。表示なし・差分ありなら全件を取り消して再ドラッグを受け付ける。通常の短いドラッグでも押下中にプレビューを出す。取消・ロード時は元のEntityだけの色を戻し、表示記録を破棄する。[登録解除](../../../../crates/hw_world/src/map/stockpiles.rs#L25)・[ロード時のリセット](../../../../crates/bevy_app/src/systems/save/reset.rs)

| テスト配置と操作 | 合格となる結果 |
| --- | --- |
| Aは`y=10, 10 ≤ x ≤ 13`の4セル（両端含む）。離れたBは2セル、Tank付属は2セル。`(10,10)`だけを囲む | プレビューと確定の直接対象は`{(10,10)}`、断片は空。Aは3セル。Bと付属2セルのEntity、座標登録、所有関係、在庫は操作前と一致 |
| Aを`10 ≤ x ≤ 14`に広げ、中央の12を除く | 同じ行で直接`{12}`、断片`{10,11}`、残存`{13,14}`。複数成分を囲んでもこの規則を各成分に適用 |
| 建設中／完成／旧セーブ復元後のTankだけを囲む。別ケースでプレビュー後に対象1セルを差し替えるか、所有Yardを変更する | 設備だけなら直接・断片は空。差替え時は他の対象を含めて削除0件。新Entityの色は変わらず、次の正常なドラッグで表示どおりに確定 |

- [x] 純粋な集合テスト、通常の解除システムを通すECSテスト、実機での色付きセルと確定結果の照合を通す。[物流仕様](../../../logistics.md)・[建築仕様](../../../building.md)

### M2　読めなかった設定と、保存途中の旧設定を保護する

現行はファイル不存在・解析失敗・読取エラーのいずれでも既定値で起動する。通常終了時は設定を操作していなくても同じ場所へ直接書く。既存提案R02の一時ファイルを使った置換に加え、起動時の読込結果を終了時まで伝える。[読込と書込](../../../../crates/bevy_app/src/systems/settings/persistence.rs#L147)・[終了時保存](../../../../crates/bevy_app/src/systems/settings/mod.rs#L97)・[既存の原子的保存](../../../../crates/bevy_app/src/systems/save/atomic_file.rs#L70)

読込結果（正常・不存在・解析失敗・読取失敗）と、起動時または最後に保存した正規化済みの設定値を保持する。画面を閉じる、Esc、通知から再試行、通常終了を同じ保存判断に通す。値を変更して元に戻した場合や同じ値のUI通知は未変更、画面外のF12による永続設定変更は変更ありとする。比較には`GameSettingsFile`の保存対象だけを使い、浮動小数点のNaNを毎回の変更として数えない。[保存と再試行](../../../../crates/bevy_app/src/systems/settings/feedback.rs#L33)・[入力経路](../../../../crates/bevy_app/src/plugins/input.rs)

| 読込時の状態 | 未変更で閉じる／終了 | 値が変わった状態で保存 |
| --- | --- | --- |
| 正常 | 原本を維持 | 同じディレクトリで一時書込・ファイル同期・置換・親ディレクトリ同期。成功後に比較用の値を更新 |
| 不存在 | 初回設定を新規作成できる | 初回は`NoReplace`。起動後に同名ファイルが現れたら上書きせず再確認 |
| 解析失敗（非UTF-8を含む） | 原本を書かない | 生バイトを読み、既存退避を上書きしない別名で同期して保存。原本を置換直前に再照合し、差替えまたは退避失敗なら中止 |
| 読取失敗 | 原本を書かない | 読取を再試行。読めない間は原本を保持し失敗を返す。読めた原本を退避・再照合してから現在値を保存 |

既存の原子的セーブから一時ファイル作成〜置換結果の返却を共用し、RON設定とv1セーブのエンコード・スロット固有の後始末は各呼出側に置く。バックアップの同期が未確定なら原本の置換前に止める。設定の置換が済み親ディレクトリ同期だけに失敗した場合は「置換済み・永続化未確認」として扱い、再試行で原本の退避が増殖しないようにする。

- [x] 隔離ディレクトリで壊れたRONと非UTF-8をそれぞれ開閉→終了し、原本バイトが一致する。明示編集時は退避バイトが元と一致し、新設定を次回起動で読める。退避名が衝突しても過去の退避を維持する。
- [x] 読取、退避同期、一時書込、置換後の同期にそれぞれ失敗を注入する。前3者は元ファイルが残り、最後は新ファイルが読め、設定画面では同期未確認を通知、終了経路ではログに残す。再試行の成功後は古い操作が失効する。旧RONの不足項目補完と計測時の終了保存スキップも維持する。[既存の再試行テスト](../../../../crates/bevy_app/src/interface/ui/interaction/intent_handler.rs#L500)・[設定仕様](../../../settings.md)

### M3　ロード先ファイルと、現在の世界の復旧準備を区別する

ロード処理は、入力セーブと、失敗時に戻すための現在の世界のコピーを順に検査する。後者の検査が落ちても、現在は同じ `InvalidData` に変換され、入力スロットが `BodyInvalid` と記録される。候補の種類を結果型で引き継ぎ、入力由来の失敗だけをそのファイルの状態に反映する。[事前検査](../../../../crates/bevy_app/src/systems/save/transaction.rs#L123)・[結果変換](../../../../crates/bevy_app/src/systems/save/load.rs#L116)・[一覧への反映](../../../../crates/bevy_app/src/systems/save/mod.rs#L181)・[通知](../../../../crates/bevy_app/src/interface/ui/notifications.rs#L623)

`CommitError::Rejected`の文字列`candidate`を、通常入力・復旧専用入力・現行世界のロールバック用コピーを表す型にする。読んだファイルと同一ハンドルから`SaveFileRevision`を取得し、要求・結果・カタログを`(slot, revision)`で対応付ける。画面で確認した版と異なる場合は再選択に戻す。版には既存のメタデータと先頭最大16 KiBの指紋を使い、一覧の作成時は本文を走査しない。[要求と結果](../../../../crates/bevy_app/src/systems/save/state.rs)・[選択の確定](../../../../crates/bevy_app/src/systems/save/catalog_ui.rs)・[版の検査](../../../../crates/bevy_app/src/systems/save/catalog.rs#L423)

| 拒否・失敗箇所 | 世界・カタログ・通知の期待値 |
| --- | --- |
| 通常入力の本文解析／候補検査、または復旧専用入力の候補検査 | リセット0回、epoch不変。本文異常は読んだ版だけに付ける。復旧専用なら`RecoveryFailed`を維持。同一ファイルの再試行を許す |
| 正常な入力の後、現行世界のロールバック用コピーが不整合 | リセット0回、epoch不変、通常状態は`Healthy`のまま。入力に異常印を付けず「現在の世界を復旧用に準備できず中止」と1件通知する |
| 書込開始後の失敗 | ロールバック成功は`ApplyRecovered`、失敗は`RecoveryFailed`。既存の復旧手順と要求1件につき最終結果1件の契約を維持する |

- [x] 既存のロールバック拒否fixtureを一覧・通知までつなぐ。同一版の再走査では本文異常が残り、外部で差し替えた版と正常ロード済みの版では消える。異常な旧版を読んだ直後に同名ファイルが差し替わるケースも検証する。カタログにヘッダーのseedと本文判定を別々に保持し、M4から同じ版へ再試行できるようにする。[拒否fixture](../../../../crates/bevy_app/src/systems/save/transaction.rs#L2043)・[結果件数のテスト](../../../../crates/bevy_app/src/systems/save/mod.rs#L336)・[通知仕様](../../../notifications.md)

### M4　環境変数を指定せず、保存した世界を起動時に再開する

通常起動は地形seedをランダムに選ぶ。v1セーブはヘッダーのseedが起動中の世界と異なるとF9からロードできない。仕様に記載された現状の回避策は、元のseedを環境変数に指定した再起動である。スロットには既に目的のseedがある。[seed選択](../../../../crates/bevy_app/src/world/map/spawn.rs#L34)・[地形生成](../../../../crates/bevy_app/src/plugins/startup/startup_systems.rs#L83)・[ヘッダー分類](../../../../crates/bevy_app/src/systems/save/format/inspect.rs#L78)・[現行制約](../../../save_load.md)

| 段階 | 実装する経路 | この段階の完了条件 |
| --- | --- | --- |
| A. 世界を作る前に選ぶ | 起動専用の最小UIとカメラを先に用意する。`scan_save_catalog`に期待seedなしを渡し、既存の固定スロットのヘッダーだけを読む。v1候補があれば「新規ゲーム／保存から再開」、候補なし・v0のみなら従来の新規開始。計測シナリオと有効な明示seed指定は従来の直接起動を優先する | 手動・自動スロットを選べる。新規開始は通常のseed決定に進む。以前の画面の操作・二重確定は受理しない。v0は既存F9の対象として残る |
| B. 選んだファイルを確かめる | `(選択セッション, slot, revision, header seed)`を固定。一つのハンドルで版と本文を読み、起動時は選択seed、F9は起動中のseedを明示して既存の解析・staging検査を使う。通過した`PreparedLoad`を保持する | 取消・差替え・本文異常なら世界生成前に選択へ戻れる。実際に読んだ版の扱いはM3に従う。別seedを選び直せる |
| C. 世界を初期化して復元する | 現在の`Startup`／`PostStartup`の連鎖を分ける。カメラ・RtT・共通UIは1回。地形配列・feature/IDテクスチャ・チャンク・境界は採用seedで作る。新規開始だけで初期資材・Soul・Familiarを生成する。再開時は選んだseedに対応する復旧可能な初期状態と描画資源を用意し、`validate_live`を通して保持した本文を既存の通常ロード取引で適用する | `Last`の適用と復元完了後にプレイを開始する。選択から完了まではワールド入力・simulation・自動保存タイマー・手動／自動保存要求を止め、選択UIと再開要求は動かす。起動処理全体の再実行を避ける |

### M6　休憩予約に、Soulが到達できる入口を使う

候補選択は定員と解体予定を調べて施設までの距離で1件を選ぶ。入口選択は近くの歩行可能マスを探す。行き止まりになった後の再探索は予約済みの施設の周りに限られる。近い休憩所の入口すべてが施錠された区画にあり、遠い休憩所には通路があるケースを再現する。[施設の選択](../../../../crates/hw_soul_ai/src/soul_ai/decide/idle_behavior/rest_area.rs#L43)・[移動判断](../../../../crates/hw_soul_ai/src/soul_ai/decide/idle_behavior/rest_decision.rs#L137)・[再探索](../../../../crates/hw_soul_ai/src/soul_ai/pathfinding/fallback.rs#L107)

新規の休憩希望と、予約済み`GoingToRest`の継続の両方で「施設・入口」の組を決める。経路探索側の2×2施設の外周12マス列挙を共有し、各入口が`is_walkable`かつ**Soulの現在地から**`WalkabilityConnectivityCache`で連結と判定できるものだけを残す。該当入口のない施設は飛ばして次を調べる。施設の順位付けに使う既存の目的地と、到達判定の出発点を混同しない。決めた入口を`Destination`に渡す。[判断の2経路](../../../../crates/hw_soul_ai/src/soul_ai/decide/idle_behavior/system.rs#L251)・[連結判定](../../../../crates/hw_world/src/pathfinding/connectivity.rs)・[休憩所仕様](../../../rest_area_system.md)

定員は占有・予約・当該更新の仮予約を数え、既予約の本人は継続できる。移動中の施錠で到達不能になれば元の枠を解放し、通常の再判定で他施設へ向かう。探索予算切れの`Deferred`は予約・目的地を保って次の更新に繰り越す。連結判定は既存の共有キャッシュを使い、施錠／解錠・ロード後には新しい地図を参照する。

- [x] 無配属・無作業で休憩条件を満たすSoulの通常判断を`NeedsIdleDecision`または判断周期で起動する。近くの施設は全入口閉鎖、遠方施設は1入口だけ到達可。遠方への`RestAreaReservedFor`→選んだ入口への移動→`RestingIn`を追跡する。近い閉鎖施設は予約0・入所0、遠方施設は入所後に予約0・入所1であることを確認する。
- [x] 全施設が満床／解体予定／閉鎖なら新規予約0。空き1枠に2人が到着しても占有＋予約は1以下。予算0→回復では予約を保持して入所し、移動中の施錠→解錠では古い予約を残さず再評価できる。[適用側のテスト](../../../../crates/hw_soul_ai/src/soul_ai/execute/idle_behavior_apply.rs)・[経路予算のテスト](../../../../crates/hw_soul_ai/src/soul_ai/pathfinding/system/tests.rs)

### M7　床・壁配置と保管範囲解除で、ドラッグ終了を取りこぼさない

床・壁配置とゾーン解除は、通常HUDにポインターがあるとボタン解放処理より先に戻る。ワールドで押した左ボタンをHUDで離すと始点が残り、ワールドに戻っただけでプレビューが再開し得る。モーダル開始時の取消とは別に、ゾーン**配置**にはボタン状態を先に処理する既存例がある。[床・壁の入力とプレビュー](../../../../crates/bevy_app/src/interface/selection/floor_place/mod.rs#L87)・[解除の入力](../../../../crates/bevy_app/src/systems/command/zone_placement/removal.rs#L34)・[配置時の処理と回帰テスト](../../../../crates/bevy_app/src/systems/command/zone_placement/placement.rs#L45)

床・壁の入力生成とゾーン解除で、既存ドラッグの解放・取消を、UI遮断やカーソル座標取得失敗による早期returnより前に処理する。無効な解放は始点・今回の配置数・撤去色を消してモードを待機に戻す。床・壁の生成→表示→確定の順序と、一時停止中のワールド変更禁止を保つ。停止中の解放は入力側で消費し、再開時に古いドラッグが確定しないようにする。[床・壁のスケジュール](../../../../crates/bevy_app/src/interface/ui/plugins/core.rs)・[ゾーン解除の登録](../../../../crates/bevy_app/src/plugins/logic.rs)・[モーダル入力](../../../../crates/bevy_app/src/input_actions/capture.rs#L363)

| 3操作に共通のフレーム列 | 確かめる状態 |
| --- | --- |
| ワールドで押す → 押したまま通常HUDを通る → ワールドに戻ってプレビューを出す → 地図上で離す | HUD上は表示を隠して始点を保持。戻ると同じ始点から再表示し、表示した範囲で1回確定 |
| ワールドで押す → HUD上で離す → 押さずに地図へ戻る | 解放時に始点と表示が消え、戻っても再表示しない。建設サイト・占有・削除への変更0。次の有効ドラッグは1回だけ確定 |
| 有効な地図座標なしで離す／モーダルが開く／途中で一時停止して離す | いずれもワールド変更0。モーダル開始時は既存の取消処理が所有し、再開後に始点や撤去色を持ち越さない |

- [x] ECSで床・壁の建設サイトとタイル占有を同じ入力経路から照合する。
- [x] 実機は通常速度で3操作を行い、押下中・解放・復帰・次操作を観測した。保管セルの生存はM1と照合し、床・壁は施工予定の件数を確認した。[入力の所有規則](../../../world-selection.md)・[既存の解放テスト](../../../../crates/bevy_app/src/systems/command/zone_placement/placement.rs#L163)

### M8　部屋の構造と、扉の開閉状態の更新を分ける

部屋検出の入力は建物の位置と種類・仮設状態。扉の開閉だけでも部屋を再検出する印が付き、待ち時間の後、全建物から入力を集めて既存Roomを破棄・再生成する。扉の通行可否と遮光には開閉状態が必要なので、それぞれの更新経路を個別に観測する。[部屋の入力と変更検出](../../../../crates/hw_world/src/room_systems.rs#L202)・[再構築](../../../../crates/hw_world/src/room_systems.rs#L93)・[扉の開閉](../../../../crates/hw_spatial/src/door_proximity.rs#L133)・[遮光](../../../../crates/bevy_app/src/systems/lighting/runtime.rs#L688)

1. 床・外壁・扉で閉じた2室を作り、通常の`mark dirty → validate → detect`と境界表示の同期を動かす。初期生成を反映してから、Roomと`RoomOverlayTile`の**世代込みEntity集合**を記録する。無操作の対照と、建物を動かさず開→閉→施錠するケースを用意し、各状態0.5秒以上・全体2秒超を手動の時刻更新で進める。[検出タイマー](../../../../crates/hw_world/src/room_systems.rs)・[部屋を壊す対照ケース](../../../../crates/bevy_app/src/systems/jobs/deconstruction/tests.rs#L1010)
2. 扉状態だけで生成・破棄が生じた場合は、部屋検出を起こす`Changed<Door>`だけを外す。建物の追加・除去・移動・仮設状態、周期検査、扉の通行・照明・表示の購読を維持する。
3. 同じ2室・同じ入力を再実行する。扉状態だけなら各段階でRoom・境界表示の生成0／破棄0、Entity集合も同じ。最後に外壁を1枚撤去すると対象室と境界登録が消え、他室は成立する。

- [x] 開いた扉は通行可・透光、閉じた扉は通行可・遮光、施錠時は通行不可・遮光で、表示も各状態に追従する。生成・破棄の件数で採否を決め、フレーム時間の改善を主張する場合のみ同条件の実機計測を添える。[通行判定](../../../../crates/hw_world/src/map/tiles.rs)・[遮光判定](../../../../crates/hw_infra/src/lighting/occlusion.rs)・[部屋仕様](../../../room_detection.md)
