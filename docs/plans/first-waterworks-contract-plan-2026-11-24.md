## 1. 目的とプレイの流れ

王の第一工区に給水所を一つつくる。所長は契約の期限を見て、川に寄せて取水を急ぐか、将来の混合機へ運びやすい場所に置くかを決める。使い魔に任せた工事に最初のバケツが届き、王からの報酬を受け取った時点がこの試遊版の終点である。

1. 任意ガイドで休息所を完成させ、「管理 → 契約」を開く。ガイドを飛ばした場合も同じ場所に依頼がある。
2. 契約書で工区・資材・期限・報酬を読み、地図で空きを見てから「受注する」を押す。
3. 「契約用タンクを配置」から本体とバケツ置場を指定する。木材搬入と施工を待つ。進まないときは仕事一覧や使い魔の作業方針を確認する。
4. タンクが完成すると表示が「初回給水待ち」に変わる。使い魔が取水を割り当て、Soulが対象タンクに水を1杯入れると自動で検収する。
5. 契約書で確定したDreamを受け取る。水はそのまま工区で使える。

## 3. 流用する機能と初版の範囲

休息所ガイドの8段階、本体と置場の二段階配置、木材調達、施工、バケツによる自動給水、作業方針、仕事一覧、セーブスロットは既存機能を使う。ガイドの終了・スキップ・ロードで一時進捗は消えるため、ガイド完了は契約の受注条件にしない。初期配置には木材と猫車置場があり、給水所と混合機の建設地をプレイヤーが決められる。[作業ガイド](../../crates/bevy_app/src/interface/ui/work_guide.rs)・[建築](../building.md)・[初期配置](../../crates/bevy_app/src/systems/logistics/initial_spawn/mod.rs)

工区はワールド生成時の初期Yard矩形を使い、受注後のYard拡張でも引き渡し範囲を固定する。本体4セルと置場2セルが工区内にあることが契約固有の条件。用地が埋まっていれば所長は受注前に確認し、既存の移設・解体で空けられる。新しい建築物、混合機への配送義務、ランダム依頼、契約の反復受注、布告・昇格は後続候補に置く。[初期Yardの定義](../../crates/hw_world/src/anchor.rs)・[通常の配置判定](../../crates/hw_ui/src/selection/placement/validation.rs)

## 4. 状態・期限・報酬の案

| 契約の状態 | 次に進む条件 |
| --- | --- |
| 未受注 | 受注操作が成立したら、ゲーム時計、締切、工区、報酬条件を記録し「配置待ち」へ。 |
| 配置待ち | 契約用のタンクと置場が両方確定したら「施工待ち」へ。 |
| 施工待ち | 対象の正式竣工で「給水待ち」へ。設計取消なら「配置待ち」へ。 |
| 給水待ち | 受注後、条件を満たすいずれかのタンクへの初回入水で「検収済み・未受領」へ。解体完了・工区外移設完了なら「配置待ち」へ。 |
| 検収済み・未受領 | 受領操作が成立したらDreamを加算して「受領済み」へ。検収後の移設・解体・時間経過で確定額は変化しない。 |
| 受領済み | 結果を表示し、同じワールドの後続操作は再支給しない。 |

**初回試遊の仮値**は受注からゲーム内12時間、期限内40 Dream、遅延20 Dream。現行の植林費用ではそれぞれ木2本・1本分に当たる。入水時刻が締切と一致した場合は満額。遅延は進行中の契約に重ねる表示とし、失敗終了にはしない。受領に期限は設けない。試遊で両配置の受注から初回給水までを測り、初見の操作時間と停止時間を分けて調整する。試遊前の仮値をバランスの実績としては扱わない。[ゲーム時計](../../crates/bevy_app/src/systems/time.rs)・[Dreamの既存用途](../dream.md)

## 5. 実装順と担当箇所

### 初回試遊後の改訂

1. 工区を金色の太い外周と濃色の縁、内側を示す目盛で描く。契約書からの切替に加え、受注後は通常のタンク配置中にも表示する。
2. 地図上と契約書に同じToDoを表示する。区内の本体・置場の配置、竣工、受注後の水1杯、報酬受領の順に進み、受領後は地図から片付ける。
3. 通常建築と既設の給水所も対象にする。最初に実際の給水を受けた適格なタンクで検収し、先に選んだ別の工事や以前の在庫で結果が変わらないことを確認する。
4. 二つの入口からの実機試験、通常建築での保存・再開、複数タンク・工区境界・二重受領の回帰試験を行う。台帳の所有者は `first-waterworks`、利用先は改訂版の試遊で、照合・目視と記録の後に専用出力を解放する。
5. 試遊承認後は、完成タンクの条件をToDo・給水検収・セーブ読込で共有する。地図と契約書の文面は同じ表示状態から生成し、進捗・期限境界・保存復元の既存テストで動作を照合してから公開する。

| 順 | 成果 | 実装・確認箇所と区切り |
| --- | --- | --- |
| A | 現行の工事を基準として記録 | 通常生成の同一seed・同一開始セーブで、休息所ガイドを通常操作で完走。川寄りと将来の混合機寄りでタンクを新設し、受注相当の開始点から初回給水までを計測する。初見のつまずきと、実際の搬送距離を記録。 |
| B | 契約の状態と保存を先に通す | 契約1件の状態遷移、対象の資格、期限境界、報酬確定を小さなルールとして実装。rootの保存スキーマと復元へ接続し、旧セーブを読み込めることを確認する。機能2・6・8・9の土台。 |
| C | 通常の工事から自動で検収する | 通常配置の確定、正式竣工、実入水の3か所をつなぐ。工事を2件同時に進め、工区の条件を最初に満たした給水で一度だけ検収する。機能4・6・7。 |
| D | 所長が画面だけで最後まで操作できる | 管理タブ・地図表示・契約用配置・工程表示・受領・通知・Helpを接続。機能1〜9を新規開始と途中再開の両方で試遊し、受領結果まで確認する。 |

### 状態の記録元

- **配置と竣工**。契約用配置では通常の配置判定に工区内の条件を加え、プレビューと確定で同じ条件を使う。キーは当該世界の契約と今回の指名を識別する値とし、配置のやり直しでは更新する。両方の配置が成功した場所で設計図に印を付け、竣工処理で設計図を消す前に完成建物へ移す。通常版の建設完了イベントの旧・新所有者と照合する。[二段階配置](../../crates/bevy_app/src/interface/selection/building_place/flow.rs)・[竣工処理](../../crates/bevy_app/src/systems/jobs/building_completion/mod.rs)・[建設イベント](../../crates/hw_jobs/src/events.rs)
- **給水**。既存の給水依頼は `GatherWaterToTank`、使い魔が割り当てる作業は `GatherWater`。通常版のタンク投入成功処理に、実際の格納確定に結び付く通知を加える。投入先の設備、工区、入水量を照合し、最初の成立だけを保存する。計測用の `TankPourReceipt` は検証の照合に使える。現在水量や設備の見た目から初回入水を推測する必要はない。[給水依頼](../../crates/hw_logistics/src/transport_request/producer/tank_water_request.rs)・[タンクへの投入](../../crates/hw_soul_ai/src/soul_ai/execute/task_execution/bucket_transport/phases/pouring.rs)
- **保存と報酬**。初版は受注時にワールド内に最大1件の契約記録を作り、記録が0件の旧v0/v1セーブを未受注として読む案とする。工区、指名番号、状態、締切、報酬条件、検収時刻・確定額を保存する。契約書から置いた設計図・完成タンクには同じ指名を保存し、座標や一時的なEntity番号だけで復元しない。読込候補で契約数・状態と印の整合性を検査し、同じ検査を復旧経路にも適用する。受領時は状態確認・Dream加算・受領済み化を一つの処理で確定し、その後に通知する。[保存スキーマ](../../crates/bevy_app/src/systems/save/schema.rs)・[ロードと復元](../save_load.md)
- **画面と説明**。`hw_ui`の管理枠が契約の表示と操作要求を担当し、rootがゲーム状態を読み、受注・受領を検証して反映する。タブを閉じても工事は進む。進捗を表示するためのAI再評価・経路探索は加えない。Helpには入口、工区、取水の成立条件、締切と受領方法を登録する。[管理画面](../ui-world-first.md)・[通知](../notifications.md)・[Help](../help-screen.md)

## 6. リスクと判断

- **給水されても理由が伝わらない**。ToDoの給水行に未達と達成を表示し、投入後は報酬の受領先を示す。診断は既存の仕事一覧へつなぎ、判定材料がないときは次の確認先を示す。
- **期限が立地を一択にする**。同じセーブで二つの立地を試し、初回給水までの工期と後続の混合機への運搬距離を比べる。両方を通常の指揮で選べる期限に調整する。混合機を建てるのは比較試遊時の任意操作とする。
- **保存の境目で結果が変わる**。入水時刻は同じゲーム時計の更新順に固定し、判定と受領の確定を保存スナップショットより前に置く。期限直前・ちょうど・直後、同フレームの保存で確認する。

### 2026-11-24 の確認状況

Intel ArcのVulkan実画面（1920×1080）で、生成seed `20260914` の同じ開始セーブから二つの立地を試した。どちらも「管理 → 契約」で受注し、本体とバケツ置場を指定した。通常の木材搬入・施工を経て、川でくんだ水が指名タンクに5単位入った時点で検収され、契約書から報酬を受け取れた。

| 本体の配置 | 受注から初回給水まで（ゲーム内時間） | 受領額 |
| --- | ---: | ---: |
| 川側 `(77, 56)` | 39分11秒 | 40 Dream |
| 内陸側 `(77, 46)` | 54分51秒 | 40 Dream |

内陸側は受領後に手動スロット2へ保存し、再読込後も検収時刻（1日目00:58）、40 Dreamの受領済み表示、残高116.6 Dreamが一致した。再度受け取るボタンも表示されなかった。全11画面で契約文・締切・操作ボタンを目視確認した。草地では工区線が薄く、既存の境界線と並ぶ場所では見分けにくい。

各立地1回の結果で、川側の工期が約16分短かった。期限12時間と40／20 Dreamは初回の設計値のまま。搬送の実移動距離、休息所ガイドからの通し操作、初見参加者が自力で契約を見つけて立地を選べるかは今後の試遊項目。

### 工区表示と契約ToDoの改訂後

最終版をIntel Arc／Vulkanの1920×1080画面で確認した（台帳 `first-waterworks-ui-06`、119件の入力、13場面）。川側は契約書から、内陸側は同じ開始セーブの「建てる → 水タンク」から建設した。どちらも金色の境界と内向きの目盛を確認でき、配置を終えると地図のToDoが「済」に変わって木材搬入数が表示された。最初の給水で両方とも40 Dreamを受領した。内陸側は契約の指名番号0のまま達成し、再読込後も受領済みで、残高は手動スロット2に保存した135.73929 Dreamと一致した。

## 8. ロールバック

試遊で進行上の問題が見つかった場合は新規の受注を止める。既に保存した工事と検収結果・受領済み報酬を維持し、修正版で続きから再開できるよう保存互換を確認する。

## 9. AI引継ぎメモ
